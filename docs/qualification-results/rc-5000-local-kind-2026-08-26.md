## Resource recommendation and claim boundary

The measured run used an agent request/limit of 32 MiB/128 MiB per selected Node and a collector request/limit of 64 MiB/256 MiB. P95 usage was about 62.7 MiB per agent and 159.7 MiB for the collector, so the old requests did not represent observed scheduling demand. The resulting chart recommendation raises requests to 96 MiB per agent and 192 MiB for the collector while retaining the measured limits. Re-qualify before lowering limits, increasing live density, changing the five-second agent interval, changing the four-read admission bound or publishing a provider-specific sizing recommendation.

The 16 GiB figure is the Docker Desktop allocation required by this four-node local harness and its synthetic workload. It is not a Kubernetes production-node sizing recommendation. Configured store ceilings remain rejection bounds, not live capacity claims.
